# 验收与 GPT 应用适配

## 验收层

1. 结构：文件、链接、frontmatter、YAO。
2. 程序合同：枚举、冲突、锁定、差异组、模式授权与错误输入。
3. 模型行为：真实自然语言输出；不能仅断言命中关键词即理解正确。
4. 图片效果：仅在真实生成后审查锁定、妆、身份和阵容；不由文本推断。
5. 应用保存：更新后重新打开，逐字比较完整指令、文件清单、开场白、能力和可见性。
6. 应用行为：新对话输入普通需求、不加“别生图”；然后验证用户明确生图可触发可选能力。图片生成必须保持开启。

每层分别 PASS / FAIL / PARTIAL / UNVERIFIED。应用默认模式失败时，不宣布整体稳定，也不能通过关闭可选能力或给每条测试补“不要生图”隐藏失败。

骨相回归至少覆盖：普通原创自动写出三区关系；柔和骨相锁定不会被锐化；局部改妆不改已有骨相、不补未知深度；五人同妆仍逐对满足差异目标；参考深度不足不制造事实。核对完整输出的关系和锁定，不把出现“骨相”二字当通过。真实图片中的骨相遵循另列 UNVERIFIED，直到有获准生成与可见结果。

## 导出

运行 `python3 scripts/export_gpt.py --out OUTPUT_DIR`，输出：
- instructions.txt：同一真源的决策规则、结构和妆容适配。
- knowledge-lexicon.md：词汇候选与来源，不再承载优先于指令的另一套行为规则。
- app-config.json：名称、简介、开场白、可选能力。
- export-manifest.json：源文件与生成文件哈希，用于追溯。

脚本不联网、不登录、不上传。应用是派生载体，不是另一份编辑真源；发现缺陷先修 Skill 再导出。
GPT 能力保持图片生成开启。默认文字、显式生图与否定/引用用例必须在指令正文，不能仅藏在知识文件。
不默认切换用户模型；只有真实发现某模型或模式不支持合同，先记录实际差异，再说明建议。

## 保存与诊断

网页显示输入成功不能证明受控表单或远端版本接收。填写完整指令后让页面完成自动保存，再点击更新，等待“更新待定”消失；重新打开并比较完整字符串。不要快速切换其它字段造成待保存状态丢失。
指令为空与模型忽略正确指令是不同问题，要分别保留证据。
如果编辑器预览正常、正式新对话误生图，应检查正式版本、所选模型/模式以及会话是否确属目标 GPT；一次只改一项，不通过不断加禁止语句假装修复。
没有足够证据时写明平台原因未定位，保留已验证 Skill；不得宣称“开启生图就一定自动生图”。
