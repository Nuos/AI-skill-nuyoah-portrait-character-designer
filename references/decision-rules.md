# 四视图决策规则

## 一、模式与范围

普通“设计、定妆、四视图、改提示词”默认文字。只有当前请求明确要求实际生成图片或编辑图片本身才调用图片工具。上传参考图、上一轮生成过、引用“直接出图”并要求改写，都不自动授权生图。脚本只整理与校验文本，不调用模型、不联网、不读参考图文件。

默认对象是一个人物的一套四视图。多人物先拆成多个独立人物资产；同一人物的国王、落魄、老年等状态分别建版本，不混进一张四视图。只有用户明确要求单独肖像或局部妆容任务时，复用原面部模块，不强行扩成四视图。

## 二、建立最小设计合同

保留原始请求；记录 character.id、asset_version、性别描述、外观年龄、时代文化、身份锚点、身体比例、肤质、毛发、妆容、服装、配饰、姿态、参考范围和交付尺寸。没有指定的精确年龄、身高与头身比用 null 或“未指定”；不擅自补成固定默认值。自由描述保留在角色 notes，执行者负责把硬约束落到字段与提示词。

已确定项优先于模板。风格、职业或气质不能覆盖脸型、年龄和身体；国籍、时代与地域不自动推出族裔、肤色或性格。“不分性别”指接受任何性别设定，不是强行中性化；“不分年龄”不是不呈现年龄；“不分年代”不是混搭年代。

参考角色、参考妆服、参考姿态必须区分。参考身份只保留可见证据，不从照片认人、判断真实年龄或敏感属性。遮挡、侧光和单张正面无法确认的结构保留未知；为补齐背面所作的新设计应明确为保守补全。

## 三、局部改造

“保持同一人物，只换服装”先保存 baseline_character，按 allowed_paths 检查变更。身份编号不变；未授权的脸、外观年龄、肤色、体型与发型不得一起变化。需要同时换时代、妆发时，分别列出允许路径。批准新造型后更新资产版本，并同步四列。

原提示词有冲突时优先采用用户最近明确的对应要求；不能牺牲其它锁定项来让检查通过。只有会实质影响人物身份且无法保守处理的信息才问一个必要问题；其它可逆选项采用明确的草案，不重复询问已给信息。

## 四、输出与审查

默认一句方向与一块完整中文提示词；不默认展示 JSON、评分、内部审查表或推理过程。每个提示词完整展开人物基准、四视图布局、妆服、身体、摄影及防漂移要求。单张独立视图也必须带同一完整基准，不能只写“生成侧面”。

先检查请求锁定，再检查身份和时代，再检查四列方向、同尺度与裁切，最后检查表面细节。四视图不是四个不同脸，不执行旧阵容的“拉开差异”规则。图片结果必须实际观看；关键词齐全、JSON PASS 或存在文件都不证明图像合格。失败只修定位到的问题；不擅自改原意或无限重生成。
