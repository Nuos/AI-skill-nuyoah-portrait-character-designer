# 结构选择、兼容与阵容

## 三级优先级

这是工作顺序，不是经过测量的生物识别权重；不写“必定是另一个人”。

| 层级 | 变量 | 决策作用 |
|---|---|---|
| 一级 | 整体长宽与局部纵向比例、颧部/下颌轮廓、眼形与相对位置、鼻部体量和走向 | 先构造轮廓、比例及主要五官关系 |
| 二级 | 嘴唇宽度与厚薄关系、自然眉形、眉眼距离、基础肤色 | 补充个体外观；不推断性格。肤色不计结构差异 |
| 三级 | 痣、雀斑、局部肤质、不对称、耳部或牙齿特点 | 按用户要求或可见证据保留；不强制添加 |

“脸型”只是其它轴的总结：不得同时按“窄长脸”“脸较窄”“下颌收窄”给重复差异分。骨相也不是额外万能得分；必须落到宽度、转折或投影关系。

## 选择顺序

1. 锁定用户指定特征，列出自由轴。
2. 确定整体长宽与局部纵向比例；不要把所有局部一起拉长。
3. 按下节设计眉骨/眼窝、颧部、面中、下颌/下巴与软组织；写出相对关系。
4. 选择眼裂长度、开合、眼睑、眼距与眼角方向；再选鼻背宽度/高度、鼻尖体量和走向。
5. 补嘴唇与自然眉形；肤色独立处理。
6. 用表情与妆容实现气质，不为了气质标签强行改锁定结构。
7. 比较可选候选，选择满足约束且与当前阵容较不同的一种。
不要求每张脸同时具有所有“标准美化”特征，也不强制反向丑化。

## 骨相设计与输出

每次原创人物都执行，不等用户点名骨相。先选骨架关系，再选覆盖的软组织；默认在 Prompt 中融入至少三个区域的具体关系：眉骨/眼窝、颧部、下颌/下巴。每区选有辨识作用的控制，不能只写“骨相清晰、立体高级”。极简、固定脸或局部任务服从用户范围。

- 额头与眉眼：考虑额头前后倾向、眉骨起伏与眼窝深浅。眉骨不是眉毛，眼窝不是双眼皮褶皱；平缓眉骨、浅眼窝同样是有效设计。
- 颧部：分别考虑横向宽度、高低位置与向前突出程度，按需写清与太阳穴、面颊的过渡。颧位高不等于脸宽，骨点突出不等于面颊消瘦。
- 面中：考虑鼻基底及上唇周围与颧部的前后过渡；中庭长短是纵向比例，不代表面中凸凹，高鼻梁也不自动代表面中前突。
- 下颌与下巴：考虑相对颧宽、下颌转折，以及下巴的长短、圆方尖和前伸/后收；尖不等于前伸，短不等于后缩。
- 软组织：面颊和颏部的饱满度决定表面过渡，不能把脂肪、修容或光影直接当骨骼。柔和与有结构可以共存，不给所有人深眼窝、高颧骨、锐下颌。

普通输出把三区关系并入主要结构句；侧脸、三分之四视角或强调骨相时，补面中及下巴前后关系。例：“眉骨起伏平缓、眼窝较浅，颧部横向适中且轻微前突，面颊柔和过渡到略窄的下颌，短圆下巴略向前伸。”这是组合示例，不是默认脸；不以补强为由覆盖锁定的正脸、柔光或柔和骨相。

固定人物只换妆时，原有骨相逐项保留；原稿未说明的深度也保持未说明，不趁机补全。参考图只描述可见关系，强光影下标推测，遮挡或正面无法确认的深度保持未知；新增设计须与观察分开。骨相不新增差异计数组，眉骨不能冒充自然眉形差异；脚本未编码的深度由自然语言核对。

## 冲突矩阵

硬冲突必须在输出前解决；软张力可通过分层表达；观察局限不补造。

| 情况 | 类型 | 处理 |
|---|---|---|
| 同一人物、同一状态的同一轴同时“窄”和“宽” | 硬冲突 | 按最近明确要求保留一个；优先级不能判断时询问 |
| 用户锁定圆钝下巴，候选改尖下巴 | 锁定违反 | 回到候选，恢复锁定项 |
| 下颌比颧部宽，却同时以“颧部为全脸最宽处”解释 | 空间关系冲突 | 明确额头、颧部、下颌比较范围，修正其中一条 |
| 圆脸 + 清冷，单眼皮 + 甜美，长脸 + 温柔 | 可共现 | 用妆、表情或造型实现，不能列为禁配 |
| 中庭较长 + 下庭较短 | 可共现 | 不按全脸长短粗暴否决局部比例 |
| 较高鼻背 + 宽鼻翼 | 可共现 | 高度与宽度是不同轴 |
| 大眼 + 眼距较宽 | 可共现 | 不把体量与间距误作同一维度 |
| 自然下垂眼角 + 眼线上挑 | 表现层差异 | 分开写天然眼角和画出的线，明确目标 |
| 薄透底妆 + 遮瑕覆盖较强 | 可能兼容 | 指定局部遮瑕/整体薄透；若要求全脸同时完全透与完全遮，先消歧 |
| 柔雾皮肤 + 局部湿亮唇 | 可共现 | 指向不同部位 |
| 同一唇面同一区域同时完全哑光与镜面反射 | 硬冲突/可改分区 | 按目标选一项或明确不同区域 |
| “年轻感” + 成年年龄 + 利落轮廓 | 可共现 | 年龄、比例、表演分开 |
| 单张照片中眼睛闭合或被刘海遮住 | 观察局限 | 只写可见部分，完整眼型/眼距不可确认 |
| 较深眼窝、清晰颧部只出现在强侧光中 | 观察局限 | 标注推测，不能当确定骨骼事实 |
| 固定妆容 + 不同脸部比例 | 可共现 | 保留相对落点与方向，允许范围适配 |

## 同妆不同脸的专用流程

“同一套妆”要求同一套妆容合同，不能仅保留色系。先写一段共享妆容句，固定底妆质地、眼影色彩与铺色逻辑、眼线粗细与方向、睫毛状态、腮红色彩与相对落点、唇色与质地/边缘。每个人的完整 Prompt 必须原样复用这段共享妆容句；只可在句后补必要的面积适配，不改变合同。用户未指定妆时先设计这一段，再设计人物。

例如同一套“薄透半哑光底妆、贴根平直棕色细眼线、双颊中央柔边桃粉腮红、天然唇缘的桃粉缎光唇”，不能把第二人改成斜扫腮红与丝绒唇、第三人改成果冻唇；这些是不同妆。脸型改变不授权更换妆效。“按脸适配”只调整覆盖面积和相对坐标，不替换落点逻辑、线条方向或质地。

输出五人前，内部逐人写清 face/jaw/eyes/nose/lips/brows 六组值，并核对全部十对；变化不足时换自由结构轴，不能靠给五套妆、五种发型补足。每个人的 Prompt 必须明确这六组：整体长宽与纵向比例、下颌和下巴、眼部、鼻部、唇部、自然眉毛。不能省略眉毛或只用“自然鼻唇”补齐记录。每块完整展开人物 + 共享妆容，不能只写“统一桃粉妆”或“同上”。用户固定同一人物时不使用这条差异规则。

## 阵容差异程序

先区分任务：
- 明确要求彼此不同的角色阵容：使用四组差异目标。
- 同一人物变体、亲缘相似、仅换妆：以保持相似/身份为目标，不强制四组差异。
- 用户锁定大量结构又要求不同脸：只利用自由轴；无法满足时说明约束限制，不能擅改锁定项或用痣凑数。

独立计数组：
1. face：整体长宽、纵向比例（同组至多计一次）。
2. jaw：颧部与下颌宽度关系、下颌转折、下巴。
3. eyes：眼形、开合、间距、眼睑（同组至多计一次）。
4. nose：高度、宽度、鼻尖/鼻翼（同组至多计一次）。
5. lips：嘴唇宽度与上下唇比例。
6. brows：自然眉形与眉眼距离。

明显不同阵容默认每一对至少四组变化，其中 face/eyes/nose 至少两组。只改变肤色、痣、发型、服装、妆容不计入结构差异。四组是本工具的设计门槛，不保证图像识别差异。

采样不是无约束抽词：
1. 按用户限制生成2—3个自洽候选，优先在本批次尚未覆盖的自由轴取值。
2. 用同一套离散轴比较候选与已选角色；优先最大化与最相似角色的差异，而不是只与第一位比较。
3. 先满足兼容和锁定，再拉开阵容差异，再考虑次要装饰。
4. 若差异不够，优先替换未锁定的整体比例、眼部或鼻部组，再补下颌/唇/眉，不用改肤色或加标记补数。
5. 最多两轮局部修复；无可行空间时输出具体缺口，不能无限重抽。
6. 已确定阵容在本对话内保持同一结构记录，用户说“再来五个”则避免直接复制已选组合；不声称跨会话持久记忆或真正统计随机。

## 反模板检查

检查是否无意识地重复窄小脸、较大杏眼、高细鼻梁、尖下巴、饱满小嘴这组组合。出现至少三个可以触发复核，但不是自动判坏：
- 如果用户明确选择这些特征，保留；在自由轴建立差异，不能替用户改审美。
- 如果它们只是默认补全且在阵容中重复，替换两个未锁定的主要结构组并复查。
- 单个人物不必为了躲模板而强行制造怪异或瑕疵。
- 这组是当前失败模式的提醒，不是所有模型、所有文化审美的普遍定义。

# 结构与妆容候选词表

以下是可组合的描述候选，不是各民族标准、性格分类或模型效果保证。每行优先选择一个当前值；脸型名称与组成比例不能重复当作独立差异。按本轮需求取用，不填满整张表。

## 01 脸型与比例
脸型概括：圆脸、短鹅蛋脸、鹅蛋脸、长椭圆脸、方圆脸、方脸、菱形脸、心形脸、倒三角脸、梨形脸。
整体长宽：偏短宽、均衡、偏长窄；局部比例：上庭/中庭/下庭略长或略短。
横向关系：额头较宽、颧部最宽、下颌较宽；五官分布与面部留白需说明位置。
“短圆”不证明年龄，“窄长”不证明成熟或冷漠；具体比例优于并列气质形容词。

## 02 轮廓与体量
额头侧面走向：较直立、轻微后倾、后倾较明显；与额头宽度分开。
眉骨起伏：平缓、轻微突出、突出较明显；不是自然眉毛的浓淡或弧度。
眼窝深浅：较浅、中等、较深；不是眼睑褶皱宽度，不因深色眼影自动判深。
颧部横向：内收、适中、外扩；颧位：偏高、中等、偏低；向前突出：平缓、轻微、较明显。三项独立选择，不捆绑高颧与宽脸。
面中过渡：鼻基底及上唇周围与颧部前后过渡平顺、相对偏后、相对偏前；需说明比较位置，不用高鼻梁替代。中庭长短独立处理。
下颌：窄于/接近/宽于颧部；下颌角圆滑/转折可见/明显。
下巴长度：短、适中、长；正面形状：圆钝、收尖、方；前后关系：略后收、中性、略前伸。不同轴可组合，尖不自动代表前伸。
面颊与颏部软组织：饱满、适中、较薄；骨点间过渡柔和或较直接。不能把侧光阴影直接登记为骨骼凹陷。
原创可以主动选择这些关系；参考重建中的额头倾向、面中和下巴深度需要足够视角，证据不足保持未知。三个区域的组合是设计步骤，不是默认高骨量或医学诊断。

## 03 眼部
眼裂长度：较短、适中、较长；开合：较小、适中、较大。
眼睑：单眼皮、内双、窄双、扇形双眼皮、平行双眼皮；褶皱可见程度另记。
外眼角：自然下垂、平直、上扬；眼距：较近、适中、较宽。
眼型概括：圆眼、杏眼、细长眼。杏眼/杏仁眼近义时合并，不当作两次变化。
眼窝可见投影：平缓、较深；光线不足或遮挡时写不可确认。
自然眼形与上眼睑暂时压低的表情分开；眼线方向不反写成原生眼角。

## 04 眉毛
自然眉弧：平直、柔弧、眉峰明显；粗细：细、适中、较粗；长度：短、适中、长。
眉眼距：较近、适中、较宽；眉毛密度：疏、适中、密。
妆面另记：毛流眉/柔雾眉、柔化眉头/清晰眉尾，黑/黑棕/灰棕/暖棕。
修眉与画眉可以改变视觉眉形；固定身份时保留自然眉基线。

## 05 鼻部
山根高度：低、适中、高；鼻梁高度：低、适中、高。
鼻背宽度：窄、适中、宽；走向：平直、轻微弧度。
鼻尖体量：小、适中、有量感；形状：圆润、较收束。
鼻翼宽度：窄、适中、宽；鼻尖方向：稍向下、自然、稍上翘。
每次优先挑最影响设计的两项，不同时堆完整鼻部流水账；高度与宽度可自由组合。

## 06 唇部
嘴部宽度：窄、适中、宽。
上下唇关系：上薄下厚、接近、上厚下薄；总厚度：较薄、适中、较饱满。
唇峰：平缓、柔和、清楚；静态嘴角：自然平直或轻微不对称。
嘴角上扬/下落可能是表情。人中比例与唇厚分开。
果冻唇、丝绒唇是妆效，不能替代自然唇型。

## 07 肤色
明度：很浅、浅、中等、中深、深；底调：冷粉、中性、暖黄、橄榄、金棕、红棕。
色彩受灯光、曝光和妆影响；单图不能确定光照下的绝对肤色。
肤色由独立要求、可见证据或明确创作选择决定，不由国籍推导；不计为脸部结构变化。

## 08 肤质
可选：细小毛孔、轻微绒毛、眼下细纹、局部自然反光、少量肤色不均。
真实感不必全部加入，也不自动加摄影颗粒或噪点。画面需要洁净皮肤时保留自然微纹理即可。

## 09 个人特征
可选：用户指定位置的小痣、鼻梁或双颊淡雀斑、一侧眉峰略高、轻微嘴角不对称、下巴浅凹。
默认允许零项；图中看不清的标记不能补造。相同标记不能代替身份结构，新增标记不能凑阵容差异。

## 10 底妆
覆盖：裸肌感、轻度局部遮瑕、中等覆盖；表面：柔雾、半哑光、缎光、局部水光。
落点：额头/鼻梁/颧部局部提亮；明确范围，避免全脸同时出现相互排斥质地。
清透不等于提白，局部反光不等于全脸油亮。

## 11 眼影
色相：米杏、灰褐、粉棕、桃粉、灰粉、砖红、酒红、灰蓝、灰紫、杏橘、铜棕。
方法：单色薄铺、外眼尾加深、下眼尾晕染、柔和烟熏、局部珠光。
“褶皱内加深”只在存在且可见褶皱、符合效果时用；单眼皮按睁眼可见区域安排。

## 12 眼线
贴近睫毛根部的细线、只强调外眼尾、平直短延伸、轻微上提、轻微下延、图形线条。
颜色、粗细、长度、方向、边缘锐度按需求独立选择；天然眼尾和画出的眼线分开描述。

## 13 睫毛
自然纤长、轻卷、根根分明、轻束感、强束感、外侧强调、下睫毛弱化。
粗密与卷翘是不同轴；不把无明显假睫毛误写成完全没有睫毛。

## 14 下眼睑
无明显卧蚕、自然轻微隆起、局部提亮、眼下柔和粉色、下眼尾加深。
自然隆起与画出的阴影分开；不要求人人有明显卧蚕。

## 15 腮红
色相：冷粉、桃粉、珊瑚、暖杏、砖玫瑰、红棕。
落点：面颊中央、颧部外侧、眼下、鼻梁连接双颊；范围：集中/横向展开/斜向轻延。
浓度与边缘：薄透柔边、较明显柔边、图形边缘。
按目标适配，不把某脸型和某落点设为绝对禁配。

## 16 唇妆
色相：裸粉、粉棕、玫瑰、番茄红、砖红、酒红、肉桂棕。
质地：润唇、缎光、柔雾、丝绒、哑光、镜面。
边缘：天然边界清楚、轻柔晕开、内深外浅、局部唇峰强调。
锁定“只改颜色”时不顺手改光泽、唇厚或边缘。

## 17 妆发辅助
发色：自然黑、黑棕、深棕、栗棕、冷棕；发长：耳下/下巴/齐肩/锁骨/长发。
分缝与刘海：中分、侧分、碎刘海、齐刘海、无刘海；状态：顺直、松散微卷、蓬松卷发。
造型服务具体文化或创作方向；历史复原需查对应年份资料。
发型与服装不计入面部结构差异。


## 四视图摄影与全身词表扩展（v0.3.1）

以下由用户提供的真人神话劳作者提示词拆分而来。前述面部与妆容词条完整保留。可执行真源是 [turnaround-lexicon.json](turnaround-lexicon.json)，编译器按视图、姿态和明确比例选择词条，正向句与负向词分开，负向词去重。用户硬约束优先；不能为匹配词条而改人物。

### 通用、条件与角色专用三层

通用层涵盖写实摄影、四列留白、特写局部占比、全身裁切、同尺度基线、自然皮肤、发型与衣缝连续、同一神情、准确侧背方向、柔光与无文字。条件层按站姿／坐姿／受托姿态、自然比例／明确比例路由。角色专用层含劳动肌肉、疲态、尘土汗光、破亚麻、赤足与无披风道具，只在显式选用时添加。

**188厘米、中年男性、暖调偏白、左脸旧伤、九头身、黑色中长发、米灰短袍是该角色的设定，不是通用模板默认值。** 不把男性劳作者的描述渗入女性、儿童、老人、无妆、整洁角色或其它时代。年龄、性别与时代未指定时继续保持未指定。

### 空间与摄影消歧

四视图＝人像特写＋正面全身＋标准侧面全身＋背面全身；不是四个全身方向。28%指整表宽度分配，60%仅指特写局部面部的近似视觉占比。头身比的头长取头部顶部至下巴，不计发量和鞋底；九头身是明确的英雄式造型目标，不证明真实演员具有该人体测量值。无标尺图不能精确验收188厘米。

左／右始终是人物自身的解剖侧别。展示左侧时鼻尖朝画面左，展示右侧时相反。正侧面中远侧手脚可以自然遮挡，不能为“所有手指可见”而扭转身体。特写不强求脚部入画，背面不强求表情可见；必要支撑不能被删掉来满足背面完整。

相机保持水平，全身中长焦观感，特写眼平；二者是独立取景记录，不要求用一个透视中心同时完成。柔光仍允许骨相阴影和接触阴影，不使用“绝对无阴影”。四视图共享灯位、曝光和白平衡，合理转向光影不等于肤色变化。

# 妆容与人物适配

## 先决定视觉目标

先问自己这套妆要强化轮廓、保留圆润、营造横向感、增加上提方向、柔化锐感，还是制造反差。用户已经指定妆容时不更换其主要色彩/质地。
“圆脸”“长脸”不是缺陷；没有显瘦/拉长要求时，不自动纠正它们。

每个关键妆容控制写：部位 + 颜色 + 落点/范围 + 线条/方向 + 质地/边缘 + 强度；并非每项都要长句。

## 条件适配矩阵

| 已知结构 | 本轮目标 | 候选设计 | 保留项与反证 |
|---|---|---|---|
| 较圆轮廓 | 保留圆润与自然气色 | 双颊中央柔边晕染，可横向展开 | 圆脸可以横向腮红，无“不能”禁令 |
| 较圆轮廓 | 增加向上/斜向视觉方向 | 腮红从外侧颧部向太阳穴轻延，范围适中 | 目标是妆的方向，不把脸改窄 |
| 偏长轮廓 | 增加横向色彩组织 | 双颊横向柔铺，避开不需要的向下拖尾 | 不宣称物理缩短脸；用户锁定高位斜扫时保留 |
| 天然上扬外眼角 | 柔化锐感 | 较短、较平的细眼线，柔化外侧边缘 | 自然眼角仍上扬 |
| 天然下垂外眼角 | 增加上提方向 | 外眼线轻微提起，睫毛外侧适量强调 | 不是把自然眼角改为上扬眼 |
| 单眼皮/内双/遮盖褶皱 | 睁眼时仍看见妆面 | 根据可见上眼睑区域决定眼影与线条，先核对开眼状态 | 不固定画“褶皱内加深”；没有图时保守描述 |
| 较小眼睑可见区 | 清透轻妆 | 贴根细线、局部颜色，避免描述把整个可见区铺满黑色 | 舞台/图形妆可按要求覆盖，不绝对禁粗眼线 |
| 轮廓明显、眉眼对比较强 | 降低整体攻击性 | 眉头与唇缘柔化、眼线适度、表情放松 | 骨骼与自然眉毛保留 |
| 柔和轮廓 | 增加利落感 | 清晰但适度的眉尾或唇缘，选一个主要重点 | 不自动加高眉骨和削尖下巴 |
| 自然薄唇 | 保留唇形 | 按天然边界上色，质地与色彩按需求 | 不自动厚唇化 |
| 自然薄唇 | 用户要更饱满的妆效 | 轻微外扩描唇或局部光泽，并说明是妆面 | 原生唇形记录不变 |
| 较深或橄榄倾向肤色 | 清透桃粉妆 | 以该肤色上可见的桃粉色彩关系、透明度和覆盖表达 | 不自动提白，不预设某国肤色 |
| 任意脸型 | 同一套妆迁移 | 保留主色、材质、线条方向、相对五官落点和强度，范围随比例适配 | 不要求不同脸使用相同绝对像素位置 |

表中都是可选设计策略与视觉目标，不是临床或模型效果保证。

## 默认妆容重点

默认选一个主要关注点：眼、唇、双颊或整体自然；其它部分配合。用户要舞台妆、实验妆、多重点时尊重要求。
基础肤色、薄透程度、表面反光分开；“清透”不等于“冷白”，“水光”不等于全脸油亮。
颜色写常见色相与相对饱和度；“奶茶”“豆沙”需要准确控制时补灰棕、粉棕等表达。
底妆的毛孔可见性不是“必须有雀斑”。局部反光不是摄影噪点。不要为真实感人人添加油脂、干燥纹理、斑点。

## 迁移与局部修改

固定脸换妆先锁定骨相、软组织、五官与基础肤色，原稿未知项不补全；固定妆换脸先锁定妆的色彩、材质、方向与相对落点。
“柔和一点”先减少当前主导线条的锐度/强度，不同时改脸、肤色和发型。
“只换口红颜色”保留唇形、唇缘、光泽、其它妆容和拍摄。
如果目标妆本来依靠修容改变视觉轮廓，保留原生结构记录，单独描述妆面造成的视觉印象。

# 内部设计记录与检查合同

此格式用于复杂阵容和回归验证，不要求用户填写，也不默认展示。脚本只检查记录的内部一致性；自然语言与图像是否对应、请求是否真的授权，仍由执行者核对。

```json
{
  "schema_version": 1,
  "request": {"text": "同一套桃粉妆，设计五个不同脸的成年角色", "mode": "text", "explicit_image_request": false},
  "roster_goal": "distinct",
  "same_makeup": true,
  "locks": {},
  "characters": [
    {
      "id": "A",
      "axes": {
        "face.ratio": "short", "face.midface": "short",
        "jaw.width": "medium", "jaw.chin": "round",
        "eyes.length": "short", "eyes.opening": "large", "eyes.spacing": "medium", "eyes.lid": "double", "eyes.tilt": "level",
        "nose.height": "low", "nose.width": "medium", "nose.tip": "round",
        "lips.width": "medium", "lips.ratio": "lower_fuller",
        "brows.arc": "soft", "brows.distance": "medium"
      },
      "locks": {},
      "makeup": {"palette": "桃粉", "finish": "薄透底妆、缎光唇", "direction": "平直细眼线", "placement": "双颊中央柔边"}
    }
  ]
}
```

完整示例数据中只有一个角色，所以尚不满足 distinct 的数量要求。单人设定用 single；同脸修改用 identity 并给 reference_axes；相似/亲缘目标用 related。distinct 至少两人，每一对六组中至少四组不同，其中 face/eyes/nose 至少两组。程序不把缺失轴算差异，distinct/identity 必须包含完整离散轴；single/related 可以部分记录未知信息。

axes 只接受脚本 AXES 表中的键和值；自由文本词与近义词先归一化，不能使用未定义轴、数组或重复 JSON 键躲过冲突检查。低/中/高等是创作比较，不是人体测量标准；同一阵容使用一致参照。详细自由文本可以保留在角色 prompt、observations 等字段，不参与得分。

骨相补强由执行者核对实际 Prompt：原创是否写出眉骨/眼窝、颧部、下颌/下巴的具体关系；骨架、软组织、妆面与光影是否混淆；固定脸的已知项和未知项是否保留；参考深度是否有可见依据。当前16个离散轴不覆盖眉骨起伏、眼窝深浅、颧位或面中投影，不新增第七个骨相组，不以脚本 PASS 代替这些语义检查。中庭长度对应 face.midface，不能用它编码面中凸凹；眉骨不是 brows.arc。

全局 locks 与单人 locks 均为轴值映射；两者冲突不能输出。identity 的 reference_axes 是固定身份基线，任何改变都报告失败。妆容、肤色等额外锁定由自然语言检查，不冒充本脚本已覆盖。
same_makeup 为 true 时，四个妆容合同字段必须完全一致；不同脸的具体铺色范围可在 prompt 中适配，不能改变合同。此比较不证明语义等价或图片妆容相同。

request.mode 是 text 或 image；image 必须附 explicit_image_request=true，且保留本轮完整请求便于人工核对。这个布尔值是执行者的判断，不是授权证据本身；脚本不通过“出图”关键词替执行者理解否定、引用或上下文。不联网、不生图。

执行：
`python3 scripts/check_design.py /absolute/path/plan.json`

stdout 输出 JSON 检查报告；PASS 只代表已编码合同，FAIL 列出可定位错误并以退出码1结束。输入格式错误也安全返回 FAIL，不打印堆栈或读取其它路径。阈值不足时先按结构规则修复；锁定空间不足则如实说明具体限制，不改阈值伪装通过。

# 完整中文提示词模板与输出合同

用户不用填写本表。执行者先把自然语言整理成具体选择，再交付一个完整提示词；不得把未替换占位符当成最终结果。可运行数据见 `examples/turnaround-plan.json`。

## 一、合成图的段落顺序

摄影质感 → 四列布局及目标像素 → 唯一人物身份与年龄 → 时代文化 → 身体结构与可选身高/头身比 → 肤质、毛发、妆容、服装、配饰 → 中性姿态及支撑 → 背景光线与同尺度 → 身份/服装锁定 → 参考证据与保守补全 → 精简画面约束。

模板的“特写／正面／侧面／背面”不能替换为四个不同人物；不能用四张证件照代替全身；不能裁掉手脚来迁就排版。默认浅中性摄影棚背景、柔和均匀光，不让戏剧性布景遮挡人物。角色的时代是造型设定，不要求把四视图搬到剧情场景中。

独立图提示词必须展开全部身份与服装基准，然后只保留本图的视角指令。不得写“同上一张”；不得把合成图的四列构图复制到单视图提示词。

## 二、可执行编译

```bash
python3 scripts/check_design.py examples/turnaround-plan.json
python3 scripts/build_prompt.py examples/turnaround-plan.json
python3 scripts/build_prompt.py examples/turnaround-plan.json --view side
```

脚本以结构化数据为输入，不执行自然语言理解。原始请求中的硬约束必须由执行者完整录入字段或 notes；程序通过不证明它们都已覆盖。对 fields、notes 与输出间的矛盾还需语义复核。

无图片工具时交付提示词即可，不制作伪图片。明确需要图片且宿主支持时，再将提示词和获得授权的参考图送入图片工具。工具不支持负面提示词字段时，将精简禁忌合并入正文；不虚构模型参数或 ComfyUI 工作流节点。

## 三、实际图像交付

默认生成一张四列合成定妆表。用户另外要求独立资产时，按特写、正面、侧面、背面交付四张并提供合成图；独立生成的三方向必须重新核对同一身份与尺度。不得未经核对就将四个独立人物拼接。

文件名建议 `人物编号_造型版本_视图_YYYYMMDD-HHMM.png`，时间戳采用明确时区。同步记录目标尺寸、实际像素、生成模型/版本、参考资产、是否后处理和图像审查结果；只记录实际使用过的参数。保留分辨率与视觉正确性两项验收，不以放大像素掩盖变脸或错肢。


## 四、词表消费与回归

`build_prompt.py`直接读取机器词表，不是只把范文附在文档末尾。每个视图重新按适用条件选取词条，并生成无重复负向词。人物设定来自计划字段；词表只补充摄影、几何与一致性语言，不重写性别年龄时代。

```bash
python3 scripts/build_prompt.py examples/myth-laborer-188.json
python3 scripts/build_prompt.py examples/myth-laborer-188.json --view portrait --negative-only
python3 scripts/randomized_smoke.py --seed 20260925 --count 24 --out /tmp/nuyoah-random-new
```

随机回归只写结构化计划和文本，输出目录必须为空；不调用付费生图。每组输出一个plan.json、一个合成图提示词及四个独立视图提示词。图像试测记录必须包含实际服务状态，不以随机文本数量代替图片数量。

# 验收与 GPT 应用适配

## 一、分别验收

| 层次 | 检查内容 | 证据 |
|---|---|---|
| 项目结构 | 文件、入口、版本、引用、清单哈希 | 仓库内容与程序输出 |
| 程序合同 | v1兼容；v2身份、角度、尺度、类型、局部变更 | 实际 unittest 与命令行执行 |
| 提示词语义 | 完整回应请求；不默认性别年龄时代；无冲突 | 完整输入与输出逐项核对 |

| 应用保存与行为 | 导入后的完整指令、知识、工具开关与新对话行为 | 实际宿主会话 |

每层单独 PASS / FAIL / PARTIAL / UNVERIFIED。程序测试不能代替自然语言评测；自然语言评测不能代替真实图片；未执行的层保持 UNVERIFIED。

图像至少检查：恰好四列；特写不是第四个角色；严格0°/90°/180°；一侧不是镜像；三张全身同尺度和姿态；特写独立放大；头顶手脚完整；衣服结构和单侧标记正确；无未授权的年龄、性别表现、时代与身体变化。婴儿和受托人物保留必要支撑，标记被遮挡区域。发现具体偏差后只修相关变量；最多三轮有授权的定向返修，仍不合格明确保留失败状态，不无限重试。
